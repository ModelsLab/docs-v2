Train Master turns a handful of your own images into a LoRA: a small add-on model that teaches a base model a new person, product, character or style. You send the images, Train Master trains on a dedicated GPU, uploads the LoRA to your Hugging Face account and, for most trainers, gets it ready to generate with on ModelsLab.

All endpoints live under:

```bash
https://modelslab.com/api/v6/trainer
```

## How it works

<Steps>
  <Step title="Pick a trainer">
    Choose the base model you want to train on from the [trainers table](#trainers) below. You select it with `trainer_id`.
  </Step>
  <Step title="Start training">
    Send your image URLs, a trigger word and your Hugging Face details to [Start Training](/image-generation/train-master/start-training). You get back a training `id`.
  </Step>
  <Step title="Check the status">
    Poll [Training Status](/image-generation/train-master/training-status) with that `id` every minute or two until it reads `training_completed`.
  </Step>
  <Step title="Generate with your LoRA">
    When the status response's `data.inference.status` is `ready`, it gives you the exact text-to-image request to run your LoRA. See [Use your trained LoRA](#use-your-trained-lora).
  </Step>
</Steps>

## Before you start

<AccordionGroup>
  <Accordion title="A Hugging Face account and write token" icon="key">
    Your trained LoRA is uploaded to a repo on **your** Hugging Face account, so every trainer needs:

    - `hf_username`: your Hugging Face username.
    - `hf_token`: an access token starting with `hf_`, created at [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) with **write** access.

    The request is refused if the username does not exist or the token is not valid.
  </Accordion>
  <Accordion title="Training images" icon="images">
    - Send **1 to 100** image URLs in `images`. 15 to 30 good images is a sensible target.
    - Each URL must download directly, without a login. Google Drive, Hugging Face and S3 links work as long as they are public. Every URL is checked before training starts, and the error names any image that failed.
    - Use clear, varied images of one subject: different angles, lighting and backgrounds.
  </Accordion>
  <Accordion title="Wallet balance" icon="wallet">
    Training is billed per hour of GPU time, currently **$5.14 per hour**. The first hour is charged when the GPU starts on your run, and each further hour as it begins. You need at least one hour's balance to start a run. Stopping a run ends the billing.
  </Accordion>
</AccordionGroup>

## Training steps

`training_steps` controls how long the trainer learns from your images. A good starting point is **100 to 150 steps per image**: 10 images × 150 = 1,500 steps. Fewer images need more steps per image; more images need fewer.

<Note>
  Runs are capped at **2,000 steps**. A higher value is trained at 2,000.
</Note>

## Training status

The status endpoint reports one of three values in `message` and `data.status`:

| Status | Meaning |
| :--- | :--- |
| `training_started` | Your run is queued or training. |
| `training_completed` | Training finished, or you stopped the run. |
| `training_cancelled` | Training failed. `data.response_dump` holds the reason. |

<Info>
  Each trainer runs one job at a time, so a new run can wait in the queue behind others. It still reads `training_started` while it waits, and billing only starts once the GPU picks it up. A run that has not started within 6 hours fails.
</Info>

## Use your trained LoRA

For Flux LoRA, Z-Image Turbo and Stable Diffusion runs, ModelsLab loads your LoRA for inference automatically after training. Keep polling the status endpoint and watch `data.inference`:

| `data.inference.status` | Meaning |
| :--- | :--- |
| `preparing` | Your LoRA is being loaded. Check again in a minute. |
| `ready` | Generate with it now. |
| `failed` | It could not be loaded. `message` says why. |

When it is `ready`, `data.inference.api` holds the full request to send. It calls the [LoRA text-to-image endpoint](/image-generation/community-models/dreambooth-lora) with the base model as `model_id` and your LoRA as `lora_model`:

```json json
{
    "key": "your_api_key",
    "model_id": "fluxdev",
    "lora_model": "tm-3f9a1c2b7d4e5f6a8b9c0d1e",
    "lora_strength": 1,
    "prompt": "pinkpanda, a portrait photo",
    "width": 1024,
    "height": 1024,
    "samples": 1
}
```

Put your trigger word (or instance prompt) in the prompt to call up what the LoRA learned. `data.inference.playground_url` opens the same model in the ModelsLab playground.

| Trainer | Base model (`model_id`) |
| :--- | :--- |
| Flux LoRA | `fluxdev` |
| Z-Image Turbo | `z-image-turbo` |
| Stable Diffusion, `base_model_type: sdxl` | `boziorealvisxlv4` |
| Stable Diffusion, SD 1.5 | `epicrealism-v4` |

The LoRA file itself is always in your Hugging Face repo at `https://huggingface.co/{hf_username}/{repo}`, where `repo` is the `training_id` you sent, or the training `id` if the trainer does not take one.
